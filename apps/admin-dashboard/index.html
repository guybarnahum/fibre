Appearance

How this works

Use Appearance to find groups that need better representation, test a change safely, and update only the Threads that depend on it.

1
Find what needs work

Run Scan coverage. Start with a Priority hole that has real Thread demand.

2
Get a baseline

Select the group and run an experiment. This shows how the current appearance model behaves.

3
Refine carefully

Use Refine to change only the appearance traits supported by research. Keep the change small and specific.

4
Compare before and after

Use Compare for numerical and visual before/after checks. Align eyes only when it does not hide the trait being tested.

5
Decide in Compare

Review the visuals there. Reject a weak result, or freeze a good candidate and approve it. Approval alone does not make it live.

6
Admit and migrate

Approved work appears in Calibration adoption. After that calibration is admitted and deployed, Admin marks it Admitted and highlights only the affected Threads. Use Migrate affected to update them.

Adding a group that is not in the model yet

Start from its Priority hole: inspect the affected Threads, prepare research, and run a baseline experiment. A brand-new reference group still needs the separate new-group admission step; do not copy another group's appearance or infer it from names, language, birthplace, or portraits.

Rule of thumb: research suggests; Compare is where you decide; admission makes the approved change live; World updates only the Threads that depend on it.
