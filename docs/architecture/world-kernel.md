# World kernel

The kernel owns durable laws, not intelligence strategy.

It is responsible for:

- Thread identity and lifecycle
- Event ordering and provenance
- Valid state transitions
- Relationships and lineage
- Private appraisal and participation-authorization provenance
- SHA-256 binding of authorization to every material request field
- Enforcement that full task execution follows accepted authorization
- Re-validation of requester, Thread, snapshot, policy, rationale, evidence, and recorded-obligation references before execution
- Separation of restricted disclosure strategy from audience-visible response
- Validation of bounded affect and relationship-consequence proposals
- Contracts and settlement
- Balanced ledgers
- Permissions and resource ownership
- Birth, maturity, dormancy, and retirement records

The kernel does not own a particular LLM, agent framework, personality interpretation, dignity-scoring model, social institution, or user interface.

LLM-generated proposals become validated domain commands. Protected changes require authorization and append-only events. The kernel does not decide whether a request is dignified; it verifies that private appraisal occurred, that policy and attributable evidence are recorded, that the authorization is bound to the exact request and Thread state, and that only `authorizedAction: accept` can permit full execution.

An authorization that differs from private desire must cite a recorded obligation or governing decision. In the portable prototype, that reference resolves against the Thread's own unresolved intentions. A caller-authored free-form obligation is not authoritative.

The kernel checks acceptance posture both when a disclosure strategy is chosen and when an external response is minted. Public language never becomes authorization evidence.

Fondness and resentment changes are relationship-domain proposals. The kernel validates their bounds, evidence references, and provenance before appending relationship events; cognition may not directly rewrite relationship state.

Event-backed proof of authorization origin, one-time consumption, and distributed replay prevention remain future kernel responsibilities. They build on, rather than replace, the current structural content binding.
