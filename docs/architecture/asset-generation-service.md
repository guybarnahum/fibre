# Fibre asset generation service

## Purpose

Define a provider-neutral asynchronous service for generating presentation and other derived assets without making media-generation machinery part of Thread authority or part of a cloud-specific application contract.

Thread Presentation is the first caller. The service itself is general Fibre backend application infrastructure.

```text
application-owned semantic projection
        |
        v
admissible AssetGenerationJob
        |
        v
AssetGenerationService
        |
        +--> InfraDriver.workflows
        +--> MediaGenerationProvider
        `--> InfraDriver.objects
```

`InfraDriver` owns infrastructure guarantees. `MediaGenerationProvider` owns provider-specific generation behavior. The calling Fibre domain owns the semantic decision that an asset may be generated and how the result may be presented.

## Separation from Thread authority

Asset generation must not leak provider or orchestration concerns into Thread state, the World Kernel, `PresentationServer`, or a cloud driver.

Generated media:

- is not historical evidence;
- is not autobiographical memory;
- is not remembered meaning;
- is not embodiment authority merely because it looks plausible;
- does not feed back into Thread cognition as evidence through this path; and
- may be regenerated or deleted without rewriting Thread life.

A signed or provenance-rich generated reconstruction remains a representation.

## Jobs, receipts, and completion pointers

`AssetGenerationJob` is a versioned serialized request. Its real compatibility identifier belongs in `jobVersion`, not in this architecture filename.

Conceptually a job contains:

```text
jobVersion
jobId
assetKind              image | audio | video
role
variant
brief
  description
  constraints[]
inputReferences[]
referenceObjectRefs[]
outputObjectRef
receiptObjectRef
requestedAt
providerProfile
context
```

`jobId` is stable for the same semantic generation request. Reusing the same workflow identity with different input is an integrity conflict.

The caller owns semantic sameness. Presentation expresses that decision as a SHA-256 `identityDigest`; Asset Generator maps that already-decided digest to stable provider-neutral `jobId`, final `objectRef`, and `receiptObjectRef`. Asset Generator does not inspect Thread, World, Experience, Memory, or Place data to derive identity.

A successful credentialed workflow produces immutable generated bytes plus durable provenance/receipt records. The receipt preserves the exact generation job through the linked GenerationRecord, actual provider/model/request/configuration, source/reference identities, generation time, output digest and credential linkage.

After the immutable receipt exists, Asset Generator may emit the provider-neutral completion pointer:

```text
AssetGenerationCompletion {
  completionVersion
  jobId
  receiptObjectRef
  receiptDigest
}
```

The completion pointer contains no Thread ID, World ID, Experience ID, media ID, publication status, or semantic verdict. It is a transport-safe statement only that an immutable receipt now exists. Operational workflow/transport history is not the authority for why an asset exists or whether it may be shown.

## Provider boundary

`MediaGenerationProvider` is independent of `InfraDriver`:

```text
InfraDriver
  Cloudflare / AWS / GCP / Azure

MediaGenerationProvider
  OpenAI / Google / Workers AI / other media provider
```

Provider credentials remain provider secrets. Provider-native resource IDs do not become Fibre semantic identities.

The provider receives only the approved generation brief and explicitly resolved reference objects. It returns generated bytes plus actual provider/model/request/configuration metadata. A provider adapter may not silently add Thread evidence or authority.

## Deployment/runtime boundary

The provider-neutral service does not define a cloud deployment topology. A deployment adapter may host the durable Workflow and completion transport separately as long as it preserves the same `AssetGenerationJob`, immutable receipt, and `AssetGenerationCompletion` contracts.

The Cloudflare adapter does this explicitly:

```text
Presentation Worker
    |
    | InfraDriver.workflows / ASSET_GENERATION
    | Cloudflare Workflow binding with script_name
    v
Asset Generator Worker
    |
    +--> MediaGenerationProvider
    +--> ContentCredentialSigner
    +--> InfraDriver.objects
    |
    `--> AssetGenerationCompletion
              |
              v
       Cloudflare Queue
              |
              v
       Presentation consumer
```

The Asset Generator Worker owns provider execution, credential embedding, immutable output, and the operational completion pointer. It has no Thread Presentation or World Kernel publication authority.

The Workflow uses two durable steps:

```text
1. generate credentialed asset
   -> GenerationRecord
   -> credentialed final asset
   -> StoredAssetReceipt

2. signal asset generation completion
   -> deterministic AssetGenerationCompletion
   -> durable transport
```

The first step remains non-retryable for a semantic job because provider generation is nondeterministic while final Fibre object identity is immutable. The second step is safely retryable because it only sends the same deterministic pointer to already-immutable output.

Workflow completion and Queue delivery are operational facts, not semantic publication events. The calling domain must resolve the immutable receipt, verify the exact demand/job binding and publication proof, then author its own semantic update.

## Presentation-owned demand reconciliation

The generator does not discover demand. Presentation domains compile already-authorized projections into normalized asset slots and reconcile those slots against current presentation demand:

```text
authorized presentation projection
        |
        +--> ThreadPresentationAssetPlanner
        +--> WorldPresentationAssetPlanner
        `--> ExperiencePresentationAssetPlanner
                    |
                    v
          PresentationAssetSlot[]
                    |
                    v
       reconcilePresentationAssets()
                    |
                    +--> ready / unavailable / deferred
                    +--> retained pending demand
                    +--> superseded / obsolete demand
                    `--> new deterministic AssetGenerationJob[]
```

A slot binds an entity/media role to a semantic source digest, generation brief, exact source/reference witnesses, and domain-owned context. `sourceDigest` changes when the presentation material that should affect pixels changes; operational snapshot pointers may remain witnesses without automatically redefining semantic sameness.

Reconciliation is idempotent only when the caller retains the current demand record. For an unchanged slot it reuses the **exact original job witness**, including its original `requestedAt` and context, and creates no new Workflow input. If the semantic source/brief/provider/variant changes, or an explicit regeneration key is supplied, reconciliation creates a new immutable generation identity and reports the prior current demand as superseded.

Demand persistence/dispatch and completion/publication remain calling-domain responsibilities. A later repair scheduler may rerun reconciliation over durable presentation demand state for resilience; it is not semantic authorship.

### Domain planners

Thread Presentation currently compiles:

- Place environmental reconstructions.
- Autobiographical-memory reconstructions with uncertainty preserved.
- Thread portrait as **deferred** because the current Thread presentation contract does not yet carry authorized embodiment/visual-identity grounding.
- Audio/video as deferred until matching generation providers/briefs are implemented.

World Presentation compiles presentation-owned asset requests using `WorldPresentation.visualProfile`, visual anchors, relevant temporal layers, avoid guidance, and asset-shot ideas. `WorldPresentation` remains derived/non-cognitive and cannot become WorldSpec or Genesis authority through asset planning.

Experience Presentation compiles a scene from the presented event plus optional presented Place/World/time grounding. A supplied Memory is labeled and constrained as remembered perspective rather than event fact:

```text
event/history != autobiographical memory != generated reconstruction
```

These planners author semantic briefs. Asset Generator merely validates and executes the resulting generic job.

## Thread Presentation adapter

Thread Presentation owns its planner and completion publication:

```text
ThreadPresentationPacket
ThreadMediaPacket
PresentationProvenance
        |
        v
ThreadPresentationAssetPlanner
        |
        +--> PresentationAssetSlot[]
        `--> reconcilePresentationAssets()
                    |
                    +--> eligible AssetGenerationJobs
                    `--> explicit deferred slots

AssetGenerationCompletion
        |
        v
PresentationAssetCompletionService
        |
        +--> exact durable demand/job match
        +--> receipt + GenerationRecord + credential verification
        `--> ThreadPresentationAssetPublisher
                    |
                    `--> media.ready
```

The planner may use only presentation material admissible for the slot. It must not query hidden Thread state merely to make richer media.

Place or memory reconstruction briefs must explicitly preserve:

```text
historical event != autobiographical memory != generated reconstruction
```

Uncertainty cannot become precise visual fact merely because a media model wants detail. Missing embodiment cannot be solved by inventing a canonical face.

A completion for a superseded or obsolete demand is not promoted into current Thread media merely because provider work finished later.

## Execution flow

```text
1. caller validates its authorized semantic projection
2. presentation-owned planner/reconciler creates or retains deterministic demand
3. AssetGenerationService starts an idempotent durable workflow only for newly missing demand
4. request path returns; generation is not user-request synchronous
5. workflow resolves approved immutable reference objects
6. workflow invokes MediaGenerationProvider
7. successful raw output is captured with exact generation provenance
8. content credentials are applied when required by policy
9. final bytes and durable GenerationRecord/StoredAssetReceipt are stored immutably
10. Workflow sends minimal AssetGenerationCompletion in a separate retryable step
11. calling domain resolves the immutable receipt and exact durable demand
12. superseded/obsolete completion is ignored as stale
13. current completion is re-verified against GenerationRecord, bytes and credentials
14. calling domain publishes its own semantic update
15. operational demand state advances to ready after successful completion handling
```

For Thread Presentation, step 14 is a legal, idempotent `media.ready` event authored by Presentation. Asset Generator and its completion transport never author presentation semantics.

The current credentialed path does not yet serialize terminal unsupported/policy refusal as a `StoredAssetReceipt`. Therefore terminal `media.unavailable` publication remains deferred; provider/runtime failure must not be reclassified as semantic unavailability merely to close a Workflow.

## Immutability and regeneration

Generated bytes and durable provenance records are immutable. Regeneration or another candidate uses a new deterministic identity rather than overwrite.

Reference objects are generation inputs only. Their presence does not make them identity, embodiment, historical, memory or meaning authority.

## Failure semantics

Distinguish:

```text
provider/runtime generation failure
  -> operational Workflow failure; no fabricated semantic unavailability

completion transport failure
  -> retry deterministic completion pointer; never regenerate bytes

terminal unsupported/policy outcome
  -> deferred until a durable terminal receipt/provenance contract exists

successful generation
  -> immutable final bytes + durable provenance/receipt
  -> completion pointer
  -> calling-domain verification/publication
```

Transient outages must not become permanent semantic unavailability, and deterministic policy refusal must not be retried indefinitely once the terminal-outcome contract exists.

The current credentialed Cloudflare generation step is intentionally at-most-once for one semantic job identity because the media provider is nondeterministic while final object identities are immutable. General retryable generation remains **deferred** until Fibre has an explicit attempt/staging identity that can retry safely without writing different bytes under one final object reference.

## Portability requirements

Every production infrastructure/provider combination must prove:

- workflow start is idempotent for identical identity/input;
- conflicting identity reuse fails closed;
- workflow input is replay safe;
- immutable objects cannot be silently overwritten;
- stored digest identifies persisted bytes;
- completion transport can be delivered at least once without duplicate semantic publication;
- completion messages do not carry or invent calling-domain semantic authority;
- only approved briefs/references reach the media provider;
- actual provider/model/configuration provenance is retained; and
- no provider-native ID or generated output becomes Thread semantic authority.

See [`generated-asset-provenance-and-content-credentials.md`](generated-asset-provenance-and-content-credentials.md) for the stronger provenance and Content Credentials contract, and [`presentation-asset-demand.md`](presentation-asset-demand.md) for demand/completion state and concurrency boundaries.
