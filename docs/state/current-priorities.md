# Current priorities

1. Preserve the fully closed deterministic M1 Persistent Thread Round Trip as the executable baseline. `npm run demo:m1` must continue to prove Mina's restart persistence, stale-attempt recovery, willing acceptance expression, low-dignity refusal without runtime, explicit Guardian-reject abandonment, unattended timeout, obligation-mediated `refuse -> accept` expression and discharge, replay protection, credentialed editor/database inspection, and zero active runtimes.
2. Replace M1 unresolved-intention strings with structured obligation records carrying stable identity, issuer, scope, terms, expiry, recurrence, satisfaction criteria, discharge history, provenance, and explicit visibility classification before any API or editor is permitted to create or edit obligations. Separate public standing from private obligation terms. Until then, M1 obligation identity remains exact UTF-8 prose equality and historically discharged text remains permanently spent for authorization override.
3. Define the M2 Identity and Embodiment contract before implementation: durable Thread passport, portrait and voice asset references with provenance, geography timeline, family/lineage representation, privacy boundaries, mutation/version rules, and deterministic prompt-partial inspection that proves identity differences change temporary cognition context.
4. Add an isolated worker/tool gateway with independently observed capability traces before introducing any tool-, network-, or model-capable Actor. Goal Guardian declarations are an audit layer, not a production sandbox.
5. Keep the API-backed Thread Editor non-authoritative. Every editor API request requires its per-run credential; the editor may inspect public/private lifecycle and expression records and request deterministic previews, but may not seed, accept commands, issue participation authority, write disclosure or response records, acquire runtime, run workers, freeze, abandon, repair, or mutate obligations.
6. Keep command acceptance and projection repair behind administrative authority. Command preview remains public and non-mutating; preview identity is derivable from its public receipt, so the admin token—not redaction—is the authority boundary.
7. Continue targeted adversarial hardening, especially crash/concurrency cases, mutation baselines, cross-connection races, source-integrity reporting, and any authority path added by structured obligations or M2.
8. Implement Identity and Embodiment v0 only after the M2 contract and structured-obligation authority boundary are sufficiently clear; contract work may proceed in parallel with obligation hardening.
9. Add durable relationship and developmental-history services without weakening Thread ownership, dignity, interiority, or audience-disclosure boundaries.
10. Design real external delivery and performed-action records as separate future capabilities. Do not infer delivery or action from an M1 audience-response record, Actor output, authorization, or freeze.
11. Execute the autonomous web-product-studio task-marketplace vertical slice after identity, embodiment, relationships, and the worker/tool gateway are reliable.
12. Preserve the broader Fibre ambition—social, familial, cultural, institutional, and economic life—while requiring each new layer to pass the persistence, provenance, authorization, replay, adversarial-evidence, and human-inspection standards established by M1.
