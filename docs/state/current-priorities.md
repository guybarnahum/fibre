# Current priorities

1. Continue the approved [`M1 Persistent Thread Round Trip`](../validation/m1-persistent-thread-round-trip.md) from the hardened SQLite spine and independently running local API into persistent request, appraisal, authorization, disclosure, lifecycle, replay, editor, and end-to-end stages.
2. Preserve the deterministic milestone boundary: no production LLM provider, marketplace, embodiment, family, high-availability, multi-region, or production cloud scope until the persistent round trip passes.
3. Persist named requests, SHA-256 request digests, Thread-owned appraisal-context inclusion/exclusion traces, and restricted private participation stances as the next M1 slice.
4. Persist request-bound Participation Authorization, restricted disclosure strategy, and audience-visible external response as distinct records before any externally initiated execution path.
5. Define an explicit lifecycle transition table before broadening the command vocabulary beyond the frozen/dormant `UPDATE_SELF_MODEL` proof.
6. Add exclusive thaw leases, runtime sessions, deterministic Actor and Goal Guardian workers, freeze validation, and event-backed authorization consumption.
7. Convert the static Thread Editor into an API-backed inspection and simulation tool, including access-aware private/public views, event history, integrity state, and explicit projection repair.
8. Establish repeatable behavioral evaluation, targeted mutation analysis, crash/concurrency testing, and drift baselines throughout implementation; do not treat a passing test count as sufficient evidence.
9. After M1, implement Identity and Embodiment v0.
10. Execute the web-product-studio task-marketplace vertical slice after the Thread lifecycle and identity foundations are reliable.
