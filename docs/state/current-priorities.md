# Current priorities

1. Preserve the completed deterministic M1 Persistent Thread Round Trip as the executable baseline. `npm run demo:m1` must continue to prove Mina's restart persistence, stale-attempt recovery, accepted freeze, explicit Guardian-reject abandonment, unattended timeout, obligation-mediated discharge, replay protection, credentialed editor inspection, and zero active runtimes.
2. Replace M1 unresolved-intention strings with structured obligation records carrying stable identity, issuer, scope, terms, expiry, recurrence, satisfaction criteria, discharge state, and provenance before any API or editor is permitted to create or edit obligations. Until then, M1 obligation identity remains exact UTF-8 prose equality and historically discharged text remains permanently spent for authorization override.
3. Implement persistent disclosure strategy and audience-visible external response as separate live-kernel records. Preserve the existing distinction among private stance, authorization, temporary cognition, freeze, performed action, disclosure strategy, and requester-visible communication; deterministic Actor output must not be mistaken for external expression.
4. Add an isolated worker/tool gateway with independently observed capability traces before introducing any tool-, network-, or model-capable Actor. Goal Guardian declarations are an audit layer, not a production sandbox.
5. Keep the API-backed Thread Editor non-authoritative. Every editor API request requires its per-run credential; the editor may inspect public/private lifecycle records and request deterministic previews, but may not seed, accept commands, acquire runtime, run workers, freeze, abandon, repair, or mutate obligations.
6. Keep command acceptance and projection repair behind administrative authority. Command preview remains public and non-mutating; preview identity is derivable from its public receipt, so the admin token—not redaction—is the authority boundary.
7. Continue targeted adversarial hardening: individual static-path layers, upstream-response caps, HTTPS/query guards, cross-connection abandonment races, percent-encoded private-path policy, crash/concurrency tests, mutation baselines, and drift evidence.
8. Implement Identity and Embodiment v0 on top of the persistent lifecycle baseline.
9. Add durable relationship and developmental-history services without weakening Thread ownership, dignity, or interiority boundaries.
10. Execute the autonomous web-product-studio task-marketplace vertical slice after identity, embodiment, relationships, and the worker/tool gateway are reliable.
11. Preserve the broader Fibre ambition—social, familial, cultural, institutional, and economic life—while requiring each new layer to pass the same persistence, provenance, authorization, replay, and human-inspection standards established by M1.
