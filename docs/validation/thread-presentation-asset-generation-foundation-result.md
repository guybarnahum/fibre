# Thread presentation asset-generation foundation — validation handoff

## Status

**NEEDS MAINTAINER VALIDATION.**

This result records the provider-neutral asynchronous asset-generation foundation added after the `insidefibre.com` P3 consumer tests/build/Cloudflare dry-run passed.

It does not claim that Cloudflare asset generation or a real image provider is already operational.

## Capability proved by this slice

The slice is intended to prove that Fibre can:

1. derive admissible still-image generation jobs from an already-valid Thread presentation packet;
2. schedule those jobs asynchronously through the general `InfraDriver.workflows` capability;
3. keep generation-provider logic outside `InfraDriver`;
4. write generated bytes immutably through `InfraDriver.objects`;
5. persist an immutable generation receipt independently of workflow retention;
6. convert a completed Thread-presentation receipt into a legal `media.ready` / `media.unavailable` presentation event;
7. refuse to invent missing embodiment merely to satisfy a media slot.

This is infrastructure/presentation evidence, not evidence of autonomous Thread life, embodiment authority, memory formation, or causal personhood.

## Negative properties pinned

The tests intentionally require:

- generation is not performed on the request/scheduling path;
- duplicate identical workflow jobs are idempotent;
- generated bytes are stored through the infra object port;
- a separate immutable receipt persists provider/model/request provenance;
- unsupported provider capability creates no fake media object;
- Cần Thơ portrait generation is not allowed without embodiment input;
- memory-image briefs carry remembered uncertainty and reconstruction disclosure;
- deterministic source snapshot + provider profile creates deterministic job/object identities;
- `media.ready` carries a Fibre object reference rather than an R2/native cloud locator.

## Deliberately deferred

- Cloudflare `workflows` implementation;
- Cloudflare R2 `objects` implementation;
- real image provider adapter and provider benchmark;
- retryable-vs-terminal provider error taxonomy;
- generated-asset serving endpoint;
- approved embodiment reconstruction brief;
- voice/video provider execution;
- automatic projection of a ready receipt into a newly published `ThreadMediaPacket` snapshot.

These remain extension paths, not rejected capabilities or permanent constraints.

## Review posture

Seeing only this slice, Fibre should read as adding a derived-media pipeline, not as claiming richer personhood because pictures exist. The core guard is that the pipeline consumes already-authorized presentation material and produces `generated_reconstruction`; it cannot upgrade its own output into Thread-life evidence.
