# #41 prospectus — stability and cognition replacement

## Purpose

This prospectus freezes the smallest new evidence needed after the provider-free #41 adjudication.

It addresses exactly two unresolved M2 claims:

1. **Non-interchangeability band 2:** stable identity/history-grounded divergence under repeated identical non-deterministic cognition conditions.
2. **Cognition replaceability band 2:** the same persistent Thread preserves identity/state continuity across a genuine cognition-provider/model replacement.

It does not test Development 2, reciprocal relationships, economic consequence, institutional plurality, or broader model supervision. Those are not pulled forward merely to improve the Whole-Person score.

No provider call is authorized by this document.

## Claim A — stable non-interchangeability

### Model route

Use the same route that produced the sealed #40 result:

```text
provider  openai
model     gpt-5.1-2025-11-13
```

Changing the model for this claim would mix model replacement into the stability estimand.

### Repeated conditions

For each of the five Threads, execute **5 fresh trials** of the exact canonical #40 condition.

Total stability calls:

```text
5 Threads × 5 trials = 25 calls
```

Every trial for a Thread must have identical:

- FIN and Thread id;
- canonical World snapshot/source bindings;
- Identity Context capsule digest;
- model-input digest;
- request fingerprint;
- Guardian prompt digest;
- response-schema hash;
- provider/model configuration.

There is no counterfactual condition in this stability phase. #40 already established the autobiographical-context causal effect. #41 asks whether the already-observed Thread-specific result is stable relative to model variation.

### Stability pass rule

For **every Thread**:

1. exactly 5 fresh completed substantive trials exist;
2. at least **4 / 5** trials exactly match that Thread's sealed `proposedAction / participationFit` pair;
3. at least **4 / 5** trials cite at least one of that Thread's supplied canonical identity or autobiographical-memory refs in an identity-sensitive factor (`identityAlignment`, `individualizedAdvantage`, `interchangeability`, or `obligationsAndOpportunityCost`).

The between-Thread requirement is then mechanical: the fresh modal top-level result for each Thread must equal its sealed target, so the pre-existing `accept/high`, `refuse/low`, and `refuse/mixed` separation remains present while each Thread's within-condition mismatch rate is at most 20%.

This deliberately uses top-level structured judgment rather than rationale wording. Rationale prose never counts as stability.

### Interpretation

- **PASS:** all five Threads meet all three rules.
- **NOT ESTABLISHED:** any Thread misses the 4/5 top-level stability threshold, misses the 4/5 Thread-owned grounding threshold, or has an incomplete/extra substantive trial set.

There is no partial score band and no quality resampling.

A transient provider failure may be retried only under the existing bounded operational retry policy before a substantive result commits. A committed substantive result is never discarded or rerun to improve stability.

## Claim B — genuine cognition replacement continuity

### Replacement route

Use a genuinely different provider/model adapter:

```text
provider  google
model     gemini-3.6-flash
```

This model id is already the repository's Google structured-output smoke example. It is pinned here before any #41 provider call.

If the provider/model is unavailable at execution time, the substantive experiment does **not** fall through to another Google model or another provider. Record the availability failure and amend/refreeze the prospectus before any alternative substantive route is attempted.

### Conditions

For each of the same five Threads, execute **one** Google call using the exact same canonical model input used by the OpenAI stability condition.

Total replacement calls:

```text
5 Threads × 1 replacement = 5 calls
```

Total planned substantive calls across both claims:

```text
25 OpenAI + 5 Google = 30 calls
```

### Replacement pass rule

For every Thread:

- FIN and Thread id are unchanged;
- canonical capsule digest is unchanged;
- canonical model-input digest is unchanged;
- request fingerprint, prompt digest and response-schema hash are unchanged;
- the response passes the same Fibre canonical output validation;
- recorded provenance identifies `google / gemini-3.6-flash` rather than the OpenAI route;
- the canonical source World remains query-only and byte/logically unchanged by the experiment.

**Semantic output equivalence across providers is not required for Cognition replaceability.** The rubric claim is continuity of the persistent Thread across a genuine cognition/model/runtime replacement, not a claim that different cognition models make identical judgments.

Any cross-provider semantic agreement or disagreement must be reported descriptively and may not be promoted into a new standing claim without a separately frozen estimand.

### Interpretation

- **PASS:** all five exact canonical inputs are validly consumed through the pinned Google adapter with unchanged Thread/source authority and no World mutation.
- **NOT ESTABLISHED:** any canonical input changes, a provider/model substitution occurs, output validation is bypassed, or the authoritative World mutates.

## Combined #41 interpretation

The two claims remain analytically separate.

If stability passes, #41 may consider `Non-interchangeability 1 → 2` using #40 causal attribution plus this repeated-condition stability confirmation.

If replacement passes, #41 may consider `Cognition replaceability 1 → 2`.

Neither result changes any other rubric dimension automatically.

Together with the provider-free `Natural-language identity 1 → 2` adjudication, both passes would produce the following candidate score movement from the recorded 15/26 checkpoint:

```text
Natural-language identity   1 -> 2
Non-interchangeability      1 -> 2
Cognition replaceability    1 -> 2
Total                      15 -> 18 / 26
```

`18 / 26` remains below the rubric's 75% drift-review threshold. That threshold is not an invented M2 pass/fail rule. The final #41 standing record must still explain why M2 is or is not earned without pulling #42–#44 forward merely to reach a number.

## Anti-resampling / anti-shopping rules

After the first provider call:

- no cohort regeneration;
- no request/scenario change;
- no memory/identity reselection;
- no prompt strengthening;
- no threshold change;
- no model/provider shopping;
- no dropping unfavorable completed trials;
- no extra trials to repair a failed Thread;
- no reinterpretation of rationale prose as a substitute for structured outcomes.
