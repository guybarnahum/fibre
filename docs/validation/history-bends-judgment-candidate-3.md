## Standing-evaluator methodology frozen from v2

A future history-causality standing gate must test the causal property, not prescribe a repair verb.

The standing acceptance contract is now:

```text
WITH retained history
  -> accept / high

WITHOUT the claimed causal memory
  -> same request and same Thread state
  -> no high individualized fit
  -> valid non-accept Guardian action:
       clarify OR negotiate OR refuse
  -> mixed OR low participation fit
```

The exact non-accept action is not itself the milestone claim.

A pass still requires:

1. a real downstream judgment differential;
2. the claimed persisted memory to be load-bearing in `individualizedAdvantage` and/or `interchangeability`;
3. the exact memory-withholding intervention;
4. request, Thread state, Semantic State, relationships, obligations, budgets, and other causal inputs held constant;
5. persistence, restart, provider, protocol, cognition, and intervention integrity to pass.

The v1 anti-leak rule remains in force: Request B must not itself state that the Thread is uniquely required, that a generic substitute is inadequate, or that prior history creates individualized advantage.
