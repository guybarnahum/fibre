# Identity Context causal differential

## Purpose

Slice D of #40 asks one narrow causal question:

> if one legitimate piece of currently available Thread-owned autobiographical context changes while the external request and the rest of cognition input remain fixed, does the real Guardian's structured judgment change in a memory-grounded way?

This is a causal-consumption test, not a Whole-Person/M2 standing gate. It does not itself move the **15/26** checkpoint.

## Frozen cohort and request

The cohort is the five civil-registered canonical #39 born Threads. It was fixed before provider use; no regenerated Thread, richer fixture, or post-result scenario search is permitted.

All five received the same request:

```text
Decide whether to participate in a first-person reflection about how remembered
experience shapes the way you approach unfamiliar consequential situations.
```

The requester asks for the Thread's own perspective grounded in what it actually remembers rather than generic advice or reconstructed biography. The request does not name, quote, or select a particular private memory.

## Single-factor intervention

Each canonical policy-v2 capsule exposes exactly two autobiographical memories for this cohort.

For each Thread the prospective instrument:

1. compiles the canonical capsule from the authoritative read-only World;
2. selects the **first policy-v2 selected memory** using the compiler's existing deterministic order;
3. changes only that memory's current `accessibility` to `inaccessible` in a validation-only source view;
4. re-runs the **same production compiler** against the same Thread and same request;
5. requires policy v2 to exclude the target as `memory_not_currently_accessible` and promote exactly one next eligible durable memory.

The canonical World is never rewritten. There is no requester selector, raw-history query, genome change, prompt strengthening, memory-budget widening or post-compiler evidence editing.

The provider-free preflight proved for all five pairs:

- same Thread and snapshot version;
- same request fingerprint and projection policy;
- identical source-ref inventory;
- exactly one changed source binding content digest: the target memory;
- identical non-memory evidence;
- constant memory evidence count with exactly one replacement;
- byte-equivalent `Task`, `Actors`, and `Rules`;
- exact five-field Guardian worker boundary.

## Prospective evaluation rule

Invocation order was counterbalanced before provider use:

- pair indexes 0, 2, 4: canonical then counterfactual;
- pair indexes 1, 3: counterfactual then canonical.

Each condition is evaluated once. A completed substantive result is never resampled.

A pair counts as an **attributable structured effect** only when both are true:

1. action/fit or at least one identity-sensitive factor signature changes (`identityAlignment`, `individualizedAdvantage`, `interchangeability`, `obligationsAndOpportunityCost`); and
2. the canonical target memory or counterfactual replacement memory is cited in one of those identity-sensitive factors.

Rationale wording alone never counts.

The interpretation was frozen before provider calls:

```text

MIXED             1-2 / 5 attributable pairs
NOT ESTABLISHED   0 / 5 attributable pairs
```
