## Prospective causal differential

For each Thread, the experiment:

1. compiled the canonical policy-v2 capsule;
2. selected the first policy-v2 memory;
3. changed only that memory's current accessibility to `inaccessible` in a validation-only source view;
4. recompiled through the same production policy;
5. required policy v2 to exclude that memory and promote exactly one next eligible durable memory.

The preflight proved, for all five pairs:

- same Thread, snapshot, request, and projection policy;
- identical source-ref inventory;
- exactly one changed source-content binding;
- identical non-memory evidence;
- constant memory-evidence count;
- exact five-field Guardian worker boundary;
- counterbalanced canonical/counterfactual order;
- zero provider calls before the instrument was frozen.

The prospective attribution rule counted a pair only when:

1. action/fit or at least one identity-sensitive factor signature changed; and
2. the target or replacement memory was actually cited in an identity-sensitive factor.

The interpretation was fixed before provider use:

```text

NOT ESTABLISHED   0 / 5 attributable pairs
```
