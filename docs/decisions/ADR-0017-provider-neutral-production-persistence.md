# ADR-0017: Provider-neutral production persistence

## Status

Accepted.

## Context

Fibre already has two physical-persistence patterns in active code:

- the authoritative World/Thread and Genesis domain stores currently share a direct local SQLite consistency domain;
- Thread Presentation and Asset Generator already use the provider-neutral `InfraDriver` for ordered streams, immutable objects, catalogs, realtime delivery and workflows.

As Fibre moves from local scientific/development proofs toward production Worlds, generated media, Civil Registry identity, social/economic state and multiple runtime services, letting each service choose SQLite files, cloud databases, buckets or provider SDKs directly would make semantic behavior depend on deployment topology. It would also make atomic cross-domain operations such as birth harder to preserve across providers.

At the same time, replacing semantic stores with a generic infrastructure repository would erase important Fibre authority boundaries. A memory store, Civil Registry and World store do not become interchangeable merely because they use the same database mechanism.

## Decision

All persistent **production** state and byte objects created or consumed as durable state by Fibre services must cross a provider-neutral `InfraDriver` capability.

The dependency direction is:

```text
Fibre semantic authority
  -> domain store/repository
  -> InfraDriver capability
  -> provider adapter/mechanism
```

Domain stores remain responsible for Fibre meaning, validation, provenance, transaction participation and replay semantics. `InfraDriver` supplies physical persistence/runtime guarantees and contains no Thread, memory, birth, relationship or identity ontology.

The rule applies across all services and generated production artifacts, not only Presentation.

Specific consequences:

1. Transactional semantic state belongs behind `infra.state` once that executable capability is proven.
2. Immutable generated bytes and immutable byte-level witnesses use `infra.objects`.
3. Ordered service/delivery streams use `infra.streams`.
4. Derived lookup indexes use `infra.catalog` and never replace semantic authority.
5. Workflows, queues, coordination, secrets, cache and telemetry use the matching provider-neutral capabilities when those capabilities become executable.
6. Provider-native storage/database identifiers remain inside adapters or explicitly classified operational metadata; semantic records use Fibre IDs and `objectRef`-style identities.
7. A cross-domain Fibre transaction must retain one consistency/transaction scope even when several semantic stores participate.
8. A hydrated Thread or World JSON document is an export/projection/snapshot, not the primary live authority.

Repository fixtures, tests, checked-in scientific evidence and disposable `.fibre/` development runs are not production persistence and may continue to use local files directly.

## Migration rule

The decision is accepted before all current code has migrated.

Existing direct World Kernel SQLite persistence and the local durable model-invocation journal are explicit migration debt. They are grandfathered so this decision does not force a semantic rewrite merely for abstraction purity. They are **not precedent** for new persistence families.

Repository validation should fail detectable new production persistence bypasses while naming the current exceptions explicitly. Exception sets should shrink as migrations land.

The first `infra.state` proof will target the existing atomic Genesis birth transaction, including Civil Registry and initial Thread state. This is deliberately chosen because it exercises Fibre's strongest current transaction boundary and therefore tests whether the abstraction preserves the architecture rather than weakening it.

## Alternatives considered

### Keep SQLite as the universal Fibre storage contract

Rejected. SQLite is an excellent current local implementation, but making its API/path semantics the service contract would unnecessarily tie production topology to one mechanism and encourage provider-specific workarounds elsewhere.

### Let each service define its own cloud/storage abstraction

Rejected. Presentation, Genesis, World Kernel, economy and future social services would repeatedly reinvent the same portability and guarantee vocabulary. Fibre needs profiles over one capability bundle, not parallel cloud abstraction families.

### Replace domain stores with one generic Infra repository

Rejected. This would collapse semantic authority into infrastructure convenience and make it easier to bypass domain invariants.

### Rewrite all existing stores immediately

Rejected. The abstraction should be earned by real vertical slices. Existing SQLite behavior remains valid while migration proceeds incrementally behind conformance tests.

## Consequences

Positive:

- production topology can change without changing Fibre semantic identities and payloads;
- generated artifacts have one consistent persistence discipline;
- provider SDKs and native IDs stay at the infrastructure edge;
- atomic Fibre operations state their required guarantees instead of inheriting accidental database behavior;
- local development can remain fast and deterministic with SQLite/in-memory implementations;
- future services inherit the same rule from their first persistent feature.

Costs:

- `infra.state` and later capability ports need real conformance suites;
- current direct SQLite/file persistence remains tracked migration debt;
- a provider may be rejected for a particular authority if it cannot satisfy Fibre's required consistency scope;
- service entry points need explicit dependency injection rather than convenient global provider clients.
